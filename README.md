# Becky! フィルタ並び替え

メーラー Becky! の振り分けルールファイル `IFilter.def` を、ブラウザ上の GUI で並び替えるツールです。
Becky! はルールを上から順に評価するため、並び順で振り分けの結果が変わります。数百件のルールでも、ドラッグ&ドロップやキー操作で安全に並び替えられます。

> [!NOTE]
> **非公式ツールです。** Becky! の作者とは関係ありません。このツールについて、Becky! の作者に問い合わせないでください。

## ⚠ 安全に関する説明（使う前に必ずお読みください）

- **データはブラウザ内だけで処理します。** 読み込んだファイルの内容を外部に送信しません。解析ツールや外部 CDN も使っていません。
- **Becky! を終了してから保存してください。** 起動中に書き換えた場合の動作は確認していません。
- **保存前に自動で `.bak` を作ります（対応ブラウザ）。** 元ファイルと同じフォルダに `IFilter.def.bak-YYYYMMDD-HHMMSS` を作成し、内容を読み戻して確認してから本体を上書きします。
  - 非対応のブラウザや、フォルダの選択をキャンセル・拒否した場合は、**ダウンロードで保存**します（`.bak` と新しい `IFilter.def` の 2 ファイル）。元ファイルの置き換えは手動で行い、置き換えたあとはこのツールでファイルを開き直してください。
  - 古い `.bak-*` ファイルは、不要になったら手動で削除してかまいません。
- **使う前に、手元でもバックアップを取ってください。**
- **並び替え以外は変更しません。** 各ルールは読み込んだときのバイト列のまま保持し、保存はその連結だけで行います（再エンコードしないため、文字化けや未知の行の欠落が起こらない設計です）。保存前には、順序以外の差が無いことをバイト単位で検証します。
- **警告は目安です。** 到達不能などの警告は、Becky! の仕様の推測にもとづいています。**動作は保証しません。**

## 主な機能

- **並び替え**: ドラッグ&ドロップ、複数選択（Shift / Ctrl クリック）、キー操作、「先頭へ」「末尾へ」「N 番へ移動」、元に戻す・やり直し
- **警告表示（目安）**: 到達不能・一部到達不能・冗長・一部冗長・同一ルール内の重複。詳細ペインでは条件ごとに「どのルールに先に当たるか」を表示し、警告での絞り込みもできます
- **差分表示**: 「ルールの内容は変更なし。順序のみ変更（移動したルール: N 件）」の確認
- **`.bak` つき上書き保存**（対応ブラウザ）、またはダウンロード保存

## 動作環境

| ブラウザ | 保存方法 |
|---|---|
| Chrome / Edge などの Chromium 系（File System Access API 対応） | `.bak` を作ってから上書き保存 |
| 上記以外（Firefox / Safari など） | ダウンロード保存（元ファイルの置き換えは手動） |

## 使い方

1. **開く**: 「ファイルを開く」で `IFilter.def` を選びます（Becky! のメールボックスのフォルダにあります）。
2. **並び替える**: ドラッグ&ドロップやキー操作で並び替えます。移動したルールには「元 #N」が表示されます。警告と差分を確認してください。
3. **保存する**: Becky! を終了してから「保存」を押します。初回の保存では、`IFilter.def` のあるフォルダを選ぶ画面が出ます（`.bak` を同じフォルダに作るため）。

試すときは、架空データのサンプル [`samples/IFilter.sample.def`](samples/IFilter.sample.def) を使えます。

### 画面の操作

| 操作 | 内容 |
|---|---|
| ファイルを開く | `IFilter.def` を読み込む |
| 保存 | 確認ダイアログのあと保存する（並び順が変わっていないときは押せません） |
| 元に戻す / やり直し | 並び替えの取り消し・やり直し |
| 差分 | 読み込み時との比較を表示する |
| 先頭へ / 末尾へ | 選択したルールを先頭・末尾へ移動する |
| N 番へ移動 | 選択したルールを指定した番号の位置へ移動する |
| 絞り込み | すべて / 警告あり / 到達不能のみ（絞り込み中はドラッグ&ドロップできません） |

### キーボードショートカット

Mac では Ctrl の代わりに ⌘ も使えます。

| キー | 内容 |
|---|---|
| ↑ / ↓ | 選択を上下に動かす |
| Shift + ↑ / ↓ | 範囲選択を広げる・狭める |
| Shift + クリック / Ctrl + クリック | 範囲選択 / 個別に選択を追加・解除 |
| Ctrl + A | 表示中のルールをすべて選択 |
| Esc | 選択を解除 |
| Alt + ↑ / ↓ | 選択したルールを 1 つ上・下へ移動（飛び飛びの選択は間隔を保ったまま） |
| Alt + Home / End | 選択したルールを先頭・末尾へ移動 |
| Ctrl + Z | 元に戻す |
| Ctrl + Y / Ctrl + Shift + Z | やり直し |

### 警告の種類（目安）

前提（推測）: ルールは上から評価され最初に一致したものだけが効く、1 ルール内の条件は OR、文字列は部分一致で大文字小文字を区別しない。

| 警告 | 意味 |
|---|---|
| 到達不能 | すべての条件が、先にあるルールに当たってしまう（1 つ以上は別のフォルダへ振り分けられる） |
| 一部到達不能 | 一部の条件が、先にある別の振り分け先のルールに当たってしまう |
| 冗長 | すべての条件が、先にある同じ振り分け先のルールに当たる（消しても結果が変わらない可能性） |
| 一部冗長 | 一部の条件が、先にある同じ振り分け先のルールに当たる |
| 同一ルール内の重複 | 1 つのルールの中に同じ条件が複数ある |

判定の詳細は [SPEC.md §5.6](SPEC.md#56-警告目安) を参照してください。

## 開発者向け

### 必要なもの

- Node.js 22.12 以上（`.nvmrc` あり）

### コマンド

```sh
npm ci              # 依存のインストール
npm run dev         # 開発サーバー
npm test            # テスト（Vitest）
npm run typecheck   # 型チェック
npm run build       # ビルド（dist/）
npm run gen:sample  # scripts/samples/IFilter.sample.txt から samples/IFilter.sample.def を生成
```

### 実ファイル検証

手元の実ファイルで、読み込み → 保存のバイト完全一致などを確かめます。出力はルール数・件数・一致/不一致だけで、ファイルの内容やパスは出しません。環境変数が無いとき（CI など）はスキップされます。

```sh
IFILTER_REAL_PATH=/path/to/IFilter.def npm run test:real
```

### 公開前チェック

実データ（実ファイル・実在のアドレスやドメイン・フォルダ名）がリポジトリに入っていないことを確かめるスクリプトです。出力は件数と「ファイル名:行番号」だけで、一致した文字列は表示しません。

```sh
npm run check:domains   # example.com / .jp / .org と許可リスト以外のドメインが無いか（CI でも実行）
npm run check:dist      # ビルド成果物に外部 URL への参照が無いか（npm run build のあとに実行）
npm run check:public    # 全履歴を対象にした総合チェック（手元専用。検索語は標準入力で渡す）
```

`check:public` は、実データに含まれる文字列（メールボックス ID の一部など）を 1 行に 1 つずつ標準入力で受け取り、全履歴から探します。検索語をファイルやシェルの履歴に残さないよう、次のように実行してください。CI では実行しません（検索語を CI に渡さないため）。

```sh
read -rs T && printf '%s\n' "$T" | npm run -s check:public
```

検査は許可リスト方式ですが、一般的でない TLD の裸のドメイン、全角や難読化した表記、日本語の固有名詞は見逃すことがあります。`check:public` が出力する架空サンプルの一覧を、目で確認して補ってください。許可リストは `scripts/public-check/allowlist.mjs` にあります（追加するときは理由を書く）。

### 構成

```
src/core/     パース・シリアライズ・並び替え・警告判定（UI 非依存。単体テストあり）
src/ui/       React の画面・状態管理・ファイルの読み書き
tests/        Vitest のテスト
scripts/      サンプル生成・公開前チェック
samples/      架空データのサンプル
```

`src/` では `console.*` を使いません（実データがログに出ないようにするため。テストで検査しています）。

### GitHub Pages

`.github/workflows/pages.yml` が、`main` への push で typecheck → test → ドメイン検査 → build → dist 検査 → Pages へのデプロイを行います。使うには、リポジトリの Settings → Pages → Source を「GitHub Actions」にしてください。

サブパス（`https://<ユーザー名>.github.io/<リポジトリ名>/`）で公開するため、ビルド時の `base` は環境変数 `VITE_BASE` で指定します（ワークフローではリポジトリ名から自動で設定）。手元で確かめるときは次のようにします。

```sh
VITE_BASE=/repo-name/ npm run build
VITE_BASE=/repo-name/ npm run check:dist
npx vite preview --base /repo-name/
```
